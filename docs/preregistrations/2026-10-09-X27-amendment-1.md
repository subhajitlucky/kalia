# Amendment 1 to X27 — the reverse stream leaks the future; the arm is withdrawn

Registered 2026-10-09, before any X27 GPU time was spent.

## What the first implementation attempt found

The registered design (`2026-10-09-X27-rcaa-reverse-attention.md`, freezing the
2026-09-28 plan) has the reverse stream "flip the sequence, apply the same
causal MHA, flip back". Implemented exactly that way, the stream at position
`p` attends to original positions `q >= p`: flipping makes the causal mask
causal *in flipped coordinates*, which is anti-causal in real ones. The
design's own motivation says so out loud -- "so that position t can attend to
what follows it" -- and that is precisely the defect: for a next-token model,
position `p`'s representation is used to predict token `p+1`, which the reverse
stream has just read.

**The causality test caught it.** `tests/test_rcaa.py`'s first version changed
the tokens after position 12 and asserted the outputs before it were unchanged;
they were not. No GPU hour was spent.

**What R-P2 would have been.** The pre-registered "forward val <= control +
spread" check would have been passed spectacularly -- a leaked model predicts
its own answers -- and R-P1's gap movement would have been an artefact of the
same leak. The arm could not have produced a trustworthy positive at all.

## Decision

1. **X27 is withdrawn.** No RCAA kernel is launched. The config flag remains as
   a tripwire that raises with this amendment's name; the class is deleted.
2. **The non-leaking repair is defined and deliberately not run.** Reverse-order
   aggregation of the causal prefix (attend original `q <= p`, in reverse
   temporal order) carries no information the forward stream does not already
   have -- same visible set, independent weights. Its prior for closing a
   5-nat gap is approximately zero, and quota is not spent on it.
3. **The gap stays open.** Future registrations may attack it from the
   objective side (a jointly trained backward-prediction head, which predicts
   the *previous* token and cannot leak) or by changing the model class to
   non-autoregressive (infilling/denoising), each with its own design document
   and pre-registration. Neither is registered by this amendment.

## What this buys, and what it is

A design flaw found by a test instead of a 3-GPU-hour run: the fourth
silent-null-class defect caught before quota was spent (D51, I19, I20), and
the first one that lived in a *design* rather than in code. The class of
defect is the project's characteristic risk -- a mechanism that looks wired
and cannot produce a readable number -- and this time the number would have
looked *too good*, which is how future leakage usually announces itself in
small-model research.
