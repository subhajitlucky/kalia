# Pre-registration — X38: a counterfactual residual bottleneck at 58M

Registered: 2026-10-28, before any GPU time on X38. Related: D63, X36, X37,
`docs/research/2026-10-28-invention-portfolio.md`.

## Why this exists

X36 proved the repo can make a memory that keeps names — and measured the
price: **+0.076 nats** of language quality, because the workspace took capacity
from the LM path. X37 proved the repo can make a codebook that stays alive —
and measured the failure: all 64 rules used **uniformly**, because nothing
forced them to specialize.

X38 asks a different question: can a **training signal** shape a stable
representation without paying a language-modelling tax, if the signal is
confined to a low-rank **decomposition** of the residual update? The mechanism
is not a memory and not a router. It is a way of splitting each block's
residual delta into a stable component and a volatile component, with the total
sum unchanged. The language path sees the sum; the counterfactual loss sees
only the stable component.

If it works, the claim is a mechanism-level paper, not a frontier claim:

> A low-rank counterfactual residual decomposition improves systematic
> sensitivity in a small LM without a language-modelling tax.

## The mechanism

At block `l`, the residual update is

```text
delta_l = attn_l(norm(x)) + mlp_l(norm(x + attn_l(...)))
```

A shared low-rank decomposition splits it:

```text
stable_l   = U D delta_l          # D: d -> r, U: r -> d, r << d
volatile_l = delta_l - stable_l
s = s + stable_l
v = v + volatile_l
x = s + v
```

Because `stable_l + volatile_l = delta_l`, the sum `x` follows the **standard
residual exactly**. The LM loss is invariant to `U` and `D` by construction;
only the counterfactual loss trains the decomposition. The stable stream is a
low-rank causal summary; the volatile stream carries the surface form.

At the final layer, the stable stream is pooled over the real tokens and
RMS-normalised. The counterfactual loss is:

- **invariant pairs** (meaning-preserving): minimise `||z(x) − z(x')||²`;
- **sensitive pairs** (meaning-changing): minimise `max(0, m − ||z(x) − z(x'')||²)`.

The model must learn which edits preserve meaning and which do not.

## Why this is not just a known trick

The nearest prior work is counterfactual **invariance** as a training
objective for classification and alignment — e.g. "Counterfactual Invariance to
Spurious Correlations" (2021), "Aligning Language Models Towards Counterfactual
Invariance" (2026) — and a residual-projector method for vision-language models
("Counterfactual Residual Contrastive Learning", 2026). Those apply a
representation-level loss to a model's hidden state or a post-hoc projector.
X38's candidate novelty is the **architectural decomposition of every block's
residual update with an invariant sum**, so the counterfactual gradient is
confined to a low-rank stream and the language path is unchanged by
construction. That is the claim the micro tests; a prior-art check must be
repeated before any paper submission.

## Design

- **Base:** `configs/micro-muon.yaml`, 6 layers × 384 dim × 6 heads, context
  512, Muon, QK-Norm, no soft-cap, 763 steps, seeds **1338/1339**.
- **Arms:**

| arm | split | CF loss | params |
|---|---|---|---:|
| `control` | no | no | 29,921,280 |
| `split` | yes | no | 29,970,432 |
| `loss` | no | on pooled hidden state | 29,921,280 |
| `crb` | yes | on stable stream | 29,970,432 |

The split/CRB difference is **0.16%**; `split` is the parameter-matched control
for `crb` (same decomposition, no CF loss). `loss` isolates the CF loss
without the split. `control` is the standard-model anchor. The split-only arm
must reproduce the control's forward logits within floating-point tolerance;
that is a correctness check, not a result.

- **Counterfactual pairs:** a deterministic, rule-based generator with held-out
  templates and names.
  - Invariant subtypes: consistent entity rename, synonym substitution.
  - Sensitive subtypes: subject/object swap, negation, number change, spatial
    change.
  - Train and eval use **disjoint template IDs and name sets**; the eval pairs
    are never seen in training.
  - The generator writes `train.jsonl`, `eval.jsonl` and an audit manifest with
    counts, examples and SHA-256 hashes.
- **LM data:** the same micro corpus and token budget as X36/X37. No new corpus,
  no replay, no mixture change.
- **Training:** 763 steps, batch 16 × grad-accum 8, LR 6e-4, Muon; identical
  across arms except the model flags, the CF weight and the seed. The CF batch
  is 8 pairs, every step, for the `loss`/`crb` arms. The CF loss weight is 0.1.

## Metrics

1. **Canonical 100-batch val** (`eval_val.py`, seed 1234), the registered
   language-quality number.
2. **Swap sensitivity** — the X37 protocol: 20 frozen stories, 384 prompt
   tokens, 128 reference-continuation tokens, first two capitalised names
   swapped, `NLL(swapped) − NLL(original)`. Mean over stories.
3. **Paraphrase invariance** — held-out invariant pairs: normalised squared
   distance `d = ||h0 − h1||² / (||h0||² + ||h1||²)` on the pooled final hidden
   state `h`. Lower is better.
4. **Greedy entity retention** — the X36 short-context protocol, greedy
   continuation only: fraction of prompt entities present in 64 generated
   tokens. Secondary; the full 8-candidate oracle is not run at 30M.
5. **Stable-stream usage** — effective rank and mean norm of the pooled stable
   state on a val batch; plus the relative change of `U`/`D` from
   initialisation.
6. **Ruler** — the seed spread of `split` on val, swap and paraphrase; the
   `loss` arm's val and swap are reported.

## Bars

| ID | Prediction | Threshold |
|---|---|---|
| **C-1** | The CF signal does not cost language quality | `crb val − split val ≤ +0.005`, both seeds |
| **C-1b** | The decomposition is a reparameterisation | `split val − control val ≤ +0.005`, both seeds |
| **C-2** | CRB is more sensitive to a causal edit | `crb swap − split swap ≥ max(split seed spread, +0.01)`, both seeds same direction |
| **C-3** | CRB is more invariant to a paraphrase | `crb paraphrase ≤ split paraphrase − 0.01`, both seeds |
| **C-4** | CRB does not lose entity retention | `crb greedy retention ≥ split − 0.005`, reported with both seeds |
| **C-5** | The stable stream is alive and trained | effective rank > **8**, mean stable norm > **0.01**, relative change of `U`/`D` > **1e-3**, both seeds |
| **C-6** | The pair audit is clean | no train/eval template or name overlap; the audit manifest verifies |

A win requires **C-1, C-2, C-3 and C-5**; C-1b, C-4 and C-6 are guards.

## Decision rule (fixed now)

- **C-1, C-2, C-3 and C-5 pass** → the CRB is a candidate. Register the 58M
  confirmation (control vs CRB, 2 seeds, 1,000–2,000 steps) when quota allows.
- **C-1 passes, C-2/C-3 fail** → the counterfactual signal does not shape
  behaviour at 30M; close this implementation or change the pair design, not
  the eval.
- **C-1 fails** → the CF gradient costs language quality even through the
  low-rank stream; no scale.
- **C-5 fails** → the decomposition is dead or collapsed; fix the mechanism
  before reading C-2/C-3.
- **`loss` ≈ `crb` on C-2/C-3** → the split is not the lever; report that the
  CF loss alone does the work and do not scale the split.
- **`split` differs from `control` on C-1b** → the sum invariant is broken or
  the optimizer is affected; stop and debug, do not interpret C-2/C-3.

## What this does not establish

- Not a 58M result; the 30M micro is a screen.
- Not a capability claim: the pairs are synthetic, the corpus is small and the
  context is 512.
- Not a novelty claim until the prior-art check is repeated. The closest work
  is counterfactual invariance training and residual-projector methods; the
  candidate novelty is the invariant-sum decomposition.
- Not a claim that the volatile stream is interpretable; it is simply the
  complement of the stable stream.

## Cost and stopping

8 arms × 763 steps at 30M ≈ **8–10 GPU-h**, plus CPU final evals. The current
weekly GPU quota is nearly exhausted (0.87h; reset 2026-10-31T00:00:00Z), so
the run waits for the window; the registration does not expire. If the quota
is insufficient, the 30M screen runs first and the 58M confirmation waits for
the next window. If the decomposition collapses (C-5 fails), stop and debug;
do not tune the eval.
