# Pre-registration — X64: 150M depth-expand

Registered: 2026-11-09, before the X64 smoke/full runs.

## Question

Does depth-expanding v0.3.1 from **10 → 38 layers at width 512**
(**147,803,904 params**) and continuing pretraining on the same 2.4B-token
corpus improve the standard 9-task mean by **+10%** (0.4258 → 0.468) without
losing the multimodal capabilities?

This is a clean scale control, not an architecture experiment.

## Model

- v0.3.1 architecture unchanged: width 512, 8 heads, context 1024, tokenizer
  50,257, QK-Norm, logit soft-cap, SwiGLU, RoPE.
- `n_layer: 38`; layers initialized by **linear interpolation** between
  adjacent v0.3.1 layers (`tools/depth_expand.py`); embedding, final norm and
  LM head copied.
- Continued pretraining on the same `train.bin` (2.4B tokens), fresh cosine:
  LR 3e-4, Muon 0.01, 200-step warmup, 4,770 steps, micro-batch 2 ×
  grad-accum 128, effective 512 sequences/step on 2 GPUs.
- No head-wise Muon in this clean run; that is a separate arm.

## Smoke gate (before the full run)

- Expanded init val loss within **0.15** of v0.3.1’s **2.7579**.
- ≥100 optimizer steps without OOM; throughput recorded.
- If the init loss is outside the gate, the interpolation is wrong and the full
  run does not start.

## Bars

| ID | prediction | threshold |
|---|---|---|
| **S-1** | held-out val loss | ≤ 2.70 |
| **S-2** | standard 9-task mean | ≥ 0.468 (+10%) |
| **S-3** | capability regression after adapter re-fit | captioner held-out ≥ 0.99, see→draw→see ≥ 0.90, self-verify ≥ 0.95, constraints ≥ 0.98, edit compiler within 2 pp, audio within 2 pp |
| **S-4** | from scratch; no distillation; artifacts | pass |

## Decision rule

- **S-1…S-3 pass:** promote the 150M to the public base (v0.x; the user decides
  when it is v1). The 58M v0.3.1 remains the fallback.
- **Any fail:** keep v0.3.1 as the public base; log the scale boundary. No
  tuning after the result.

## Cost

- Full run ~100 GPU-h (multi-week at 30 GPU-h/week); smoke ≤ 3 GPU-h.
