# Pre-registration — X59: 64×64 three-object diffusion capacity test

Registered: 2026-11-09, before the X59 GPU run.

## Context

X58 showed the 64×64 three-object **captioner** is excellent (held-out 0.997,
seen 0.999, blind/shuffled 0.000), but the 3.75M U-Net diffusion reached only
**0.695** exact on generated scenes against the 0.80 bar. Training loss fell
to 0.001–0.01, so the failure is not undertraining. The likely bottleneck is
diffusion capacity.

## Question

Does a larger 64×64 diffusion clear the 0.80 generated-scene bar with the same
data and schedule?

## Treatment

- **UNetLarge**: 8,708,451 params. Channels 96/192/384 instead of 64/128/256,
  plus a self-attention block at the 8×8 bottleneck (64 tokens, 8 heads).
- Same 64×64 three-object data (13,824 combos), same bidirectional caption
  embeddings, same 30k steps, batch 64, AdamW, lr 2e-4.
- Same from-scratch 6-head classifier for generated-image quality.
- Frozen X58 captioner (held-out 0.997); no captioner retraining.
- No external vision weights; no distillation.

## Bars

| ID | prediction | threshold |
|---|---|---|
| **X59-1** | generated-scene classifier exact | ≥ 0.80 |
| **X59-2** | see→draw→see loop held-out exact | ≥ 0.80 |
| **X59-3** | imagine edit survival at 64×64 | ≥ 0.70 |
| **X59-4** | from scratch; artifacts | pass |

## Decision rule

- **X59-1…X59-3 pass:** release **v0.9.0-vision-64** with the 64×64 checkpoints
  and a new morph/dream/edit gallery.
- **Any fail:** the 64×64 three-object task is beyond this scale/data; log the
  boundary, keep **v0.8.0-imagine** (32×32) as the release. No tuning after the
  result.
- Public base remains v0.3.1.

## Cost

≤ 6 GPU-h.
