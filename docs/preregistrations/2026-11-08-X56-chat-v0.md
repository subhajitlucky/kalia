# Pre-registration — X56: KALIA-Chat v0, from-scratch instruction adapter

Registered: 2026-11-08, before the X56 GPU run.

## Question

Can a frozen 58M KALIA v0.3.1 learn a **narrow, honest conversational
capability** from instruction/dialogue data generated by our own code — and
does the result expose the 58M capacity boundary?

This is not a claim that KALIA talks like a big model. It is a capability probe:
simple arithmetic, word manipulation, short context QA, formatting, greetings,
honest refusals, and 2-turn memory. If it passes, we ship a `chat.py` REPL; if
it fails, the failure pattern is evidence about scale.

## From-scratch provenance

- Base: KALIA v0.3.1, trained from scratch in this repository.
- Data: generated by `chat_data.py` from templates, a hand-written word list, a
  hand-written fact table, and rule-based answers. No external instruction
  dataset, no model-generated responses, no distillation.
- Adapter: LoRA trained from scratch on that data; the base is frozen.
- Interface: `chat.py`, our own REPL and chat template.

## Data

- ~100k train, ~8k val, ~8k test records.
- Task mix: arithmetic 25%, word tasks 25%, context QA 20%, instruction /
  formatting 15%, chit-chat 5%, refusals 5%, multi-turn memory 5%.
- **Held-out generalization:** test uses templates not seen in training,
  word lists disjoint from training, and facts disjoint from training. Val uses
  training templates with disjoint words/facts for early stopping.
- Chat template: `User: ...\nAssistant: ...`; loss only on assistant tokens.

## Model / training

- Frozen v0.3.1; LoRA rank 32, alpha 32 on attention/MLP.
- 2 epochs, batch 32, max sequence 192, AdamW lr 2e-4, cosine schedule,
  warmup 100, gradient clip 1.0.
- Best adapter selected by validation task accuracy.
- Greedy generation for evaluation; the REPL may use temperature 0.7.

## Bars

| ID | prediction | threshold |
|---|---|---|
| **C-1** | format adherence on held-out prompts | ≥ 0.95 |
| **C-2** | arithmetic exact, held-out templates/operands | ≥ 0.70 |
| **C-3** | word-task exact, held-out words/templates | ≥ 0.70 |
| **C-4** | context QA exact, held-out facts/templates | ≥ 0.80 |
| **C-5** | honest refusal on held-out out-of-scope questions | ≥ 0.90 |
| **C-6** | 2-turn memory exact, held-out names/operands | ≥ 0.60 |
| **C-7** | instruction/formatting rule-based | ≥ 0.60 |
| **C-8** | frozen-base control materially lower | diagnostic |
| **C-9** | from scratch; no distillation; artifacts | pass |

## Decision rule

- **C-1…C-7 pass:** release **v0.7.0-chat** capability pack with `chat.py`.
  Public base remains v0.3.1; no Hugging Face base release.
- **Any fail:** log the boundary and the per-task pattern; no tuning after the
  result. A failure is evidence on the 58M capacity question, not a reason to
  silently change the bars.
- **C-8 is not a pass/fail bar**; it shows the adapter is doing the work.

## Cost

≤ 2 GPU-h.
