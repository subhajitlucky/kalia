# Amendment 1 — X64 depth-expand initialization

Registered: 2026-11-10, before the amended smoke/full run.

## What failed

The X64 smoke built the 147,803,904-parameter 38-layer checkpoint by **linear
interpolation** between adjacent v0.3.1 layers. The expanded init val loss was
**8.3523**, far above the registered gate **2.9079** (v0.3.1 2.7579 + 0.15).
The smoke correctly refused to train. Linear interpolation is not
function-preserving for depth: it changes the residual stream at every
position.

## Amendment

Replace the initialization with **zero-init identity insertion**:

- Keep the 10 v0.3.1 layers, in order, at positions
  `[0, 4, 8, 12, 16, 21, 25, 29, 33, 37]`.
- The other 28 blocks are new; each copies the nearest preceding old block’s
  norms/qkv/gate/up, then sets **`attn.proj.weight = 0`** and
  **`mlp.down.weight = 0`**.
- Each new block is therefore the identity at init; the 38-layer model’s
  function equals v0.3.1, so the init val should be ~2.7579.
- Continued pretraining then lets the zero-init blocks learn.

The interpolation path remains in `tools/depth_expand.py` as the recorded
failed method; `--method zero_init` is the amended default.

## Unchanged

- Model: 38 layers × 512, 147,803,904 params; same tokenizer/data/context.
- Full run: 4,770 steps, LR 3e-4, Muon 0.01, micro 2 × accum 128, re-warm
  cosine.
- Smoke gate: init val ≤ 2.9079; ≥100 steps without OOM.
- Bars S-1…S-4 and the decision rule are unchanged.
