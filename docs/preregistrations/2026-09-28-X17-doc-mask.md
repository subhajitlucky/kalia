# Pre-registration — Doc-Mask Micro-Ablation (X17)

Registered: 2026-09-28, before any run of this experiment exists.
Related: I15 (defect, journal 2026-09-27), D43 (canonical val set),
`2026-09-28-open-source-landscape-and-transfers.md` (SmolLM3 / OLMo 3 / Llama 3
all mask across document boundaries).

## Why this is an experiment and not just a bug fix

We have a **measured defect**: the corpus is EOS-delimited, windows are sampled
without document awareness, and documents are short relative to the context. The
question is not *whether* the fix is correct — it is whether removing
out-of-document attention **improves** val loss enough to justify changing the
data path, and at what cost in throughput. That is an empirical question, and
this registers the answer in advance.

## Arms

| Arm | Config | Change |
|---|---|---|
| **control** | `micro-base` (`doc_mask: false`) | none — identical to every prior micro run |
| **treatment** | `micro-docmask` (`doc_mask: true`) | block attention + loss across EOS boundaries |

Identical in every other respect: same 30M architecture (6L × 384d, ctx 512),
same seed 1337, same data, same steps, same LR schedule. One variable.

## Protocol

- Micro scale, 500 steps, seed 1337, arms run back to back in one kernel
  (sequential, so they share the same machine state)
- Val eval every 100 steps, 20 batches (existing micro settings)
- Metric: **val loss at the final step**, plus the full val curve
- No reversibility measurement — this is a data-pipeline change, and the gap is
  architectural (D42). Measuring it here would invite exactly the
  post-hoc-narrating failure mode we registered against.

## Pre-registered predictions

| ID | Prediction | Threshold |
|---|---|---|
| **DM-1** | Treatment beats control on val loss | treatment ≤ control − **0.010** nats |
| **DM-2** | Effect is visible early, not just at the end | treatment below control at ≥ 3 of 5 eval points |
| **DM-3** | Cost is bounded | treatment step time ≤ 1.25× control |
| **DM-4** | The mask is actually engaging | mean fraction of attended positions per document < 1.0 (i.e. real masking occurs) |

DM-1 sets the bar at the **same 0.010 nats** that D15 used to reject Muon+. We
are not moving the goalposts for a fix we already believe in.

## Honest priors, recorded before the run

- **Prior: the effect is real but small.** Documents are ~200 tokens and the
  micro context is 512, so roughly two to three documents per window, and
  out-of-document context is *noise the model must learn to ignore*. Removing it
  should help modestly.
- **Prior: DM-1 may well fail at 0.010.** The attention budget freed by masking
  is small, and masked softmax over short segments can train slightly slower per
  step early on. A result in the range −0.005 to −0.015 is the most likely
  outcome, which means a large fraction of the plausible range sits *below* our
  bar. That is deliberate: the bar is set by the project's existing precedent,
  not chosen to be passable.
- **Confound we cannot remove: the micro context is 512, not 1024.** At 512 the
  boundary-crossing rate is *higher* than in the real model, so this micro
  result likely **overstates** the effect at full scale. If DM-1 passes at 0.010
  here, the full-scale gain is probably smaller. This is stated now so it cannot
  be forgotten when reading the result.
- **Not measured: throughput at full scale.** DM-3 bounds the cost at micro
  scale only. Real per-step cost at ctx 1024 must be re-checked before v0.2.1
  commits to it.

## Decision rule (fixed now)

- **DM-1 and DM-2 pass** → promote to v0.2.1, and re-baseline the canonical val
  number, because the eval must use the same masking as training to be
  meaningful.
- **DM-1 fails** → publish as a negative result. The defect is real and the fix
  stays in the codebase behind a flag, but v0.2.1 ships *unmasked* and we record
  why. We do not lower the threshold after seeing the number.
- **DM-3 fails** → the fix is correct but too slow at this scale; we report the
  cost and defer.

## Cost

~45 min of GPU, two arms at 30M / 500 steps. Scheduled **after** v0.2.0
completes so the two runs do not compete for the same T4s and so v0.2.0's own
session-3 run is not perturbed.

## Deviations

Any change to arms, steps, seed, thresholds, or the metric after this commit
requires a hash-registered amendment, as with Amendments 1 and 2. Results are
reported regardless of outcome.
