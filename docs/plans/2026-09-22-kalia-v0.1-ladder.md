# KALIA v0.1.x Ladder — Incremental Upgrade Plan

Status: active
Date: 2026-09-22

## Principle

Change **one thing per version**, behind a config flag, measured against the
previous version's loss curve. Keep winners, revert losers. Every accepted
change gets a git tag, a config, and a one-line changelog entry.

Two runs per decision:

- **Micro-ablation** (~45 min, 25M params, ~100M tokens): cheap A/B screen.
- **Full run** (58M, ~2.5B tokens): only for winners of the screen.

Data pipeline, tokenizer and optimizer state are frozen while a full run is in
progress. The `kalia-code` Kaggle dataset is never updated mid-run.

## Originality candidates (v0.2.0)

Screened with micro-ablations, then crowned by full runs:

1. **Recurrent depth (KALIA-R)** — reuse one block twice per layer: more
   effective depth per parameter. Universal Transformers exist but no current
   production LLM ships this.
2. **Planner-encoder (KALIA-P)** — a small encoder stream compresses the full
   context into "plan tokens" that the decoder cross-attends to. Decoder-only
   models dominate; a built-in planner is rare.
3. **Entity memory (KALIA-EM)** — learned memory slots for story characters, so
   names and traits stay consistent across a story. Domain-specific novelty;
   directly measurable on story data.
4. **Bidirectional prediction** — auxiliary objectives predicting both the next
   and the previous token, plus 2-ahead. Cheap; rarely combined this way at
   small scale.

## Experiment protocol

1. Freeze the reference: v0.1.0 final val loss on the held-out set.
2. For each candidate, run the micro config with the flag on and off, same seed,
   same data order. Record final val loss and tokens/sec.
3. A candidate is promoted only if it beats the reference by more than seed
   noise (> 0.02 nats at micro scale).
4. Promoted candidates get a full run; the best becomes v0.2.0 and is tagged.
5. Write down what failed and why — failed experiments are results too.

## Versioning

- Git tag per accepted version: `v0.1.1`, `v0.1.2`, ...
- One-line changelog in README under "Version history".
- HuggingFace repo keeps the latest checkpoint per version under
  `checkpoints/`; older versions move to `checkpoints/archive/`.
