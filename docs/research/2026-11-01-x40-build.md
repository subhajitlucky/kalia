## The semantics that had to be fixed

The first generator version rendered the **edited** prefix as the model input
and asked for the edited suffix. That makes the intervention already applied, so
the task collapses to ordinary continuation and I-3 would measure nothing.

The built version is:

```text
input : Intervention: rename Maya to Tessa and Leo to Rowan.
        Maya gave Leo the red book.
target: Tessa kept the book.
```

- The model sees the **factual** prefix plus an **explicit** instruction.
- The edited suffix is the LM target.
- The **edited prefix** is stored only as the input to the detached next-state
  target; it is never shown to the model.
- The instruction carries the operation arguments because `rename` is
  underdetermined without the target names, and `number`/`place` need the
  replacement values.

| pair batch | 8 | `IP_BATCH` |
| pair every | 1 step | `ip_every` |
| 30M train pairs | 16,000 (4,000 × 4 templates) | kernel `--n-train 4000` |
| 30M eval pairs | 1,050 (450 singles + 600 compositions) | kernel generator |

The state target is the edited prefix's **last-token trunk state**, detached,
before the workspace read. The head sees the factual workspace after the prompt
chunk plus a six-dimensional op vector (five ops + composition flag). The
diversity loss is the mean off-diagonal squared slot cosine plus
`1 - H(assignment)/log K`; it is zero for orthogonal slots and uniform usage.

## Why these choices

- **Factual prefix, explicit instruction.** The task is now well-posed and the
  model cannot copy the answer from an already-edited prompt.
- **Edited-prefix target.** A factual boundary state would not force a
  counterfactual representation; the edited prefix does.
- **Zero-init read, open write gate.** The LM path starts exactly as the
  control, while the state loss can train the workspace from step one. X36's
  closed gate (-4) is why this is different.
- **Multi-hot op vector.** A held-out composition is a combination of seen ops,
  not an unseen class label the head could never embed.
- **Diversity loss.** X38's stable stream collapsed to rank ~1.5; the slots
  must stay distinct and used, and I-5 checks it.

The 30M screen ran as kernel v2 at revision `2153d6f`. **I-1 failed**

`docs/journal/2026-11-01.md`; v2 is the screen. Full result:
`docs/results/x40/README.md`.

The post-hoc 2×2 benchmark (`docs/results/x40-bench/README.md`) confirms the
failure is composition, not template novelty: the clean S-P cell is at chance,
`number+place` is 0.0 and `rename+swap` ~0.25 for every arm; the above-chance
negation pairs are already handled by the control. X40 stays closed.

## What is not established

- The 30M screen is a screen, not a scaling result.
- The pair task is synthetic and the eval is a controlled 2- or 4-way
  continuation choice; it is not a general causal-reasoning claim.
- The `pairs` arm is the decisive baseline: if IP does not beat it on unseen
  compositions, the workspace/objective is not the lever.
