## The failure

The kernel then died in the evaluation loop:

```text
AttributeError: 'GPT' object has no attribute 'up'
```

The code was measuring how much the split changed from initialisation with

```python
b = getattr(model, key).weight
```

but `up`/`down` live on `model.crb`, not on the top-level model. The control and
split-s1338 arms had already been evaluated; the remaining six arms trained but
were not scored. This is a code bug in the evaluation harness, not a mechanism
result.

## The fix

- `tools/kalia_x38_crb_kernel.py` now uses `getattr(model.crb, key)` and
  asserts the module exists.
- `tools/kalia_x38_eval_kernel.py` attaches the failed run's output and runs
  **only** the registered evaluation: 100-batch val, swap, paraphrase, greedy
  retention, stable stats, C-1..C-6. It verifies the pair hashes and the failed
  run's manifest before scoring. No retraining.
- Metadata: `kaggle/kernel-metadata-x38-eval.json`.

The failed run's two completed eval rows are a sanity check: control val
**4.1468**, split val **4.1474**; the split/control difference is **+0.0006**,
inside the C-1b guard (+0.005), as the invariant-sum design predicts. The
remaining six arms are the actual test.

## The eval result — a null, with a mechanism diagnosis

The eval-only kernel completed all eight arms. The registered bars:

| bar | measured | verdict |
|---|---|---|
| C-1 CRB val ≤ split + 0.005 | **+0.0019 / −0.0025** | PASS |
| C-1b split val ≤ control + 0.005 | **+0.0006 / +0.0044** | PASS |
| C-2 CRB swap ≥ split + max(spread, 0.01) | **−0.00062 / −0.00062** | FAIL |
| C-3 CRB paraphrase ≤ split − 0.01 | **−0.02268 / +0.00258** | FAIL |
| C-4 CRB retention ≥ split − 0.005 | **−0.00069 / 0.0** | PASS (floor-limited) |
| C-5 stable rank > 8, norm > 0.01, change > 1e-3 | rank **1.48 / 1.44** | FAIL on rank |
| C-6 pair audit clean | hashes match | PASS |

**`advance = false`; no 58M scale.**

The invariant sum is free at the language level: split and control are the same
model on val, and CRB pays no language tax. But the counterfactual loss trains
the projection and then **collapses it to rank ~1.5**. A single direction that
separates the invariant and sensitive pair sets is enough to minimise the loss;
the stable stream is an edit detector, not a meaning representation. The CRB is
slightly less swap-sensitive than the split on both seeds, and its paraphrase
effect is inconsistent. The loss-only arm is the tell: it reduces paraphrase
distance on both seeds but also reduces swap sensitivity — the objective
teaches invariance, not sensitivity, on the real probe.

The C-5 rank bar was load-bearing. Without it, the trained projection and the
language-neutral val would have looked like a partial win. This is the
pre-registration doing its job.

**Next.** Close this implementation. A new registration would need a
rank/coverage or reconstruction guard, a sensitivity-only or balanced objective,
or story-level pairs. The portfolio's next bets are Relational Algebra
Attention and Predictive-Coding Depth. No 58M scale from this run.
