## The failure

The kernel then died in the evaluation loop:

```text
AttributeError: 'GPT' object has no attribute 'up'
```

The code was measuring how much the split changed from initialisation with

```python
b = getattr(model, key).weight
```

but `up`/`down` live on `model.crb`, not on the top-level model. The control and
split-s1338 arms had already been evaluated; the remaining six arms trained but
were not scored. This is a code bug in the evaluation harness, not a mechanism
result.

## The fix

- `tools/kalia_x38_crb_kernel.py` now uses `getattr(model.crb, key)` and
  asserts the module exists.
- `tools/kalia_x38_eval_kernel.py` attaches the failed run's output and runs
  **only** the registered evaluation: 100-batch val, swap, paraphrase, greedy
  retention, stable stats, C-1..C-6. It verifies the pair hashes and the failed
  run's manifest before scoring. No retraining.
- Metadata: `kaggle/kernel-metadata-x38-eval.json`.

The failed run's two completed eval rows are a sanity check: control val
**4.1468**, split val **4.1474**; the split/control difference is **+0.0006**,
inside the C-1b guard (+0.005), as the invariant-sum design predicts. The
remaining six arms are the actual test.
