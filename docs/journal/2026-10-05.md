## The launch-blocker: update arms never resumed (I18)

Auditing the generated notebooks against the plan found that Steps 2–4 invoked
`ablate.py` / `train.py` with **no `--resume` flag and no checkpoint source**.
Every continual-update arm would have trained from random initialisation
instead of the v0.2.0 checkpoint — the same failure class as the re-warm
defect (Status update 3): a mechanism never switched on, reporting a
plausible null after the quota is spent.

Fix: `ablate.py` takes `--resume-from-hub` and forwards `--resume --hub-repo`
to `train.py`; the rewarm/replay/kautilya notebooks pass
`kalia-lm/kalia-v020`; baseline stays fresh by design. `test_v030_resume.py`
reads the notebook JSON so a dropped flag fails locally rather than on
Kaggle. This is the fourth defect of this exact class the suite process has
caught before GPU spend.
