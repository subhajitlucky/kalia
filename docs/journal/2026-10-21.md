# Journal — 2026-10-21 (the quota window: the entity win falls, QK-Norm stays)

Two GPU measurements used the remaining weekly quota: the entity-holdout test
that had been canceled at 11/20, and X31's 2×2 isolation of the QK-Norm /
soft-cap bundle. A third measurement, the 2,000-sample benchmark pair, ran on
CPU and used no GPU quota. All three changed a claim the project was carrying.

## The entity 3× does not survive a held-out half

The recorded +0.061 entity-decode win picks the continuation that maximises
retention and then reports retention. The holdout kernel splits every
continuation at its midpoint, selects on the first half, and scores the second
half the selector never saw. 20 stories, 8 samples, paired bootstrap.

| selector | holdout retention (unseen half) | full-continuation retention |
|---|---|---|
| greedy | 0.0170 | 0.0296 |
| log-prob pick | 0.0103 | 0.0353 |
| **half pick (the test)** | **0.0277** | 0.0864 |
| full pick (the recorded rule) | 0.0398 | **0.0907** |
| oracle (best of the 8) | 0.0618 | — |
| human reference | 0.0803 | 0.0978 |

**half pick − greedy on the held-out half: +0.0108, 95% CI [−0.0073, +0.0318]
— not distinguishable from zero.** The full-text number reproduces exactly
(+0.0612 [+0.0389, +0.0860]), which is what a circular selector should do. What
survives is coverage: the oracle reaches 0.0618 against greedy's 0.0170, so the
right continuation is in the pool. The rule is not finding it. The half-pick
does beat log-prob-pick by +0.0175, but log-prob is below greedy on the holdout
half, so that is not a clean win either.

**M1's basis changes.** The memory-only rung was justified by this 0.061; the
programme direction now records it as a coverage/selector problem, not a proven
memory lift. The 2026-10-11 result stays in the record as measured, with the
correction attached.

**Device deviation.** The CPU protocol could not finish: ~70 minutes on story 0
of the 2026-10-21 rerun, ~20 hours for 20 stories, against a 12-hour session
limit. The completed run is GPU with the same prompts, N, 256 tokens and seeds.
The device changes the sampled continuations; `full_pick` is a re-measurement,
not a reproduction of the CPU number. The paired holdout comparison is
unaffected. Archive: `docs/results/entity-holdout/`.

## X31: the −0.08 is QK-Norm, and the soft-cap adds nothing

D8 adopted QK-Norm + logit soft-cap on one seed at 30M (3.5937 → 3.5103, a
further −0.0834). X31 ran the 2×2 at seeds 1338/1339, 763 steps, one kernel:

| contrast | seed 1338 | seed 1339 | mean |
|---|---|---|---|
| qk − control | −0.0921 | −0.0766 | **−0.0844** |
| cap − control | +0.0129 | +0.0069 | **+0.0099** |
| both − control | −0.0839 | −0.0743 | −0.0791 |

Q-1, Q-1b, Q-2a and Q-3 pass; **Q-2b fails**. The bundled gain is QK-Norm
alone; the soft-cap is slightly worse than control at both seeds and does not
add to QK. The control spread at this step pair is 0.0208, so the QK effect is
~4× its ruler.

**Decision (D55).** QK-Norm is validated at two seeds; the logit soft-cap is not
supported. Future configs keep `qk_norm` and drop `logit_softcap`; v0.2.0 is not
retro-changed. The cards, SYNTHESIS and the X31 registration carry the new
attribution. Archive: `docs/results/x31/`; verdict reproducible with
`python tools/x31_verdict.py --dir docs/results/x31`.

## The 2,000-sample benchmark pair: ARC-Easy was noise

Every zero-shot number in the v0.2.0 release was measured at `limit=500`, where
D45 measured the standard error at 1.99–2.24 pp. The 2026-10-17 review asked for
2,000; the default changed, but no run was archived. `kalia-bench-pair-2k`
scored both checkpoints in one CPU session at 2,000 samples:

| task | v0.1.2 | v0.2.0 | Δ (pp) | z |
|---|---|---|---|---|
| PIQA | 59.63 | 61.37 | +1.74 | 1.08 |
| HellaSwag | 35.60 | 35.60 | 0.00 | 0.00 |
| WinoGrande | 50.28 | 50.75 | +0.47 | 0.24 |
| LAMBADA | 25.15 | 23.90 | −1.25 | −0.92 |
| ARC-Easy | 45.95 | 46.40 | **+0.45** | 0.29 |

**The 500-sample ARC-Easy −3.80 did not replicate.** At 2,000 it is +0.45
(z=0.29). The HellaSwag +3.00 also vanished (0.00). PIQA's +2.40 shrank to
+1.74, and LAMBADA's −2.20 shrank to −1.25 but still exceeds the registered 1.0
pp allowance. No movement reaches 2σ.

**Decision (D56).** The frozen 500-sample registration is not edited: S-A FAIL
on ARC-Easy and LAMBADA remains what it produced. The public cards, README and
SYNTHESIS now report the 2,000-sample result: **S-A fails on LAMBADA only**, and
the "corpus cost 3.8 points on ARC-Easy" claim is retracted. v0.2.0 remains an
experiment release, not a promotion, because the registered rule still fails on
LAMBADA — by 0.25 pp, at z=−0.92. The loss/accuracy lesson survives in a
narrower form: a 0.2285-nat loss gain produced no 2σ accuracy movement, but it
did not cost 3.8 points on ARC-Easy.
