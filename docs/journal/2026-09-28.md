## The finding that matters most is about our own method

X18's F-3 **passes on its registered terms and means nothing.** The standard
errors on these benchmarks at `limit=500` are 1.99–2.24 pp, so the registered
0.5 pp bar sits ~4.5× below the measurement's own noise, and the observed
+1.20 pp is **0.54σ**. A 0.5 pp bar at that sample size passes about half the
time by construction.

This lands directly on the decision we are about to make: **S-A allows 1.0 pp of
regression, also below the ~2.0–2.2 pp noise floor.** The interim v0.2.0
benchmarks split cleanly once noise is accounted for:

| task | Δ vs v0.1.2 | outside noise? |
|---|---|---|
| ARC-Easy | −4.6 | **yes — a real regression** |
| LAMBADA | −4.6 | **yes — a real regression** |
| WinoGrande | −0.8 | no — within noise |
| PIQA | −0.2 | no — within noise |
| HellaSwag | +1.8 | no — within noise |

**D45** records this against our own pre-registration and sets the rule going
forward: an accuracy threshold must be stated above the measured standard error,
or with enough samples to bring the error below the bar. The registered
thresholds are *not* changed — S-A is judged on its 1.0 pp term exactly as
written, and the noise floor is published beside the verdict rather than used to
rescue it, the same handling P-C was given.

## G-0: I tested my own conclusion and it held

X18 concluded the gate was inert from a *mean*. That inference is unsafe — a gate
can be low on average and strongly variable — so G-0 was registered to attack it
before any GPU was spent, on the existing X18 checkpoint:

| quantity | value | reading |
|---|---|---|
| mean gate | 0.019172 | floor 0.017986 |
| max std across **channels** | 2.96e-04 | 1.5% relative — a near-uniform bias |
| max std across **inputs** | **5.09e-06** | **the gate ignores its input** |

The prior recorded in the pre-registration — "the real uncertainty is G-0, and it
cuts against me" — resolved against me. The data-dependent read that Gated
Residual actually claims is not operating in our arm at all.

## X19 registered, with an amendment against myself

X19 isolates the two halves of the gated arm by training `micro-branchnorm` — the
same four-branch normalisation with the gate removed, 149,952 fewer parameters.
**Amendment 1 corrects a pre-registration error I made**: G-2 claimed the arm
would be "exactly equal to control" (29,920,512 params). `RMSNorm` is affine, so
the per-branch norms are not free; the correct count is 29,922,816. The
registered number was wrong in the direction that made the arm look cheaper and
tidier than it is. A second slip in the amendment itself (the gate's share,
150,952 → 149,952) was caught by instantiating all three arms and counting rather
than trusting arithmetic on paper.

The comparison uses X18's frozen control (4.7662) and gated (4.7226) rather than
re-running them. G-1 bar is 4.7544, the midpoint + 0.010. Unlike X18's accuracy
bar, this threshold is in nats and is not under-powered.

## The legal question, answered properly

`docs/legal/training-data-licence-matrix.md`. I had assumed CDLA-Sharing-1.0
(TinyStories, 20% of the mixture) would block redistribution. Reading it, that is
wrong: **§3.5 puts Results — the outputs of Computational Use, i.e. our weights —
beyond any obligation or restriction**, and §2.1 grants Computational Use
outright. So all three text sources permit both training and weight release, and
the v0.2.0 corpus is redistributable under three cheap attribution conditions.

The unflattering asymmetry: **v0.2.0 is the licence-clean checkpoint and v0.1.2
is not.** The model that scores worse is the one whose data we can actually
ship. v0.1.2's code slice is never published.

One clause written down rather than assumed away: CDLA §1.11 caps Results at a
*de minimis* portion of the source Data, which makes memorisation a licence
question and not only a privacy one.

## Incidents

**I17 — the Kaggle dataset was silently dropping two directories.**
`kaggle datasets version` defaults to `--dir-mode skip`, which ignores
subdirectories. The `kalia-code-dev` dataset had been published flat, so
`configs/` and `eval/` were both absent and the dataset contained **zero JSON
files**. Consequence: `eval_reversibility.py` and `gate_probe.py` could not
resolve `eval/probe_sentences.json` in any kernel, which is the deeper reason
X18's Abhimanyu gap was never measurable despite `ablate.py` supporting
`--reversibility`. The upload reported success every time.
`tools/publish_code_dataset.py` now stages one layout, always uses `-r zip`,
refuses to publish an incomplete payload, and then **downloads the published
dataset back and asserts 17 required files resolve**.

**Three kernels in a row failed behind a green upload**, each a different
assumption with no assertion attached:

| kernel | failure | assumption |
|---|---|---|
| `x18-close` v1 | `FileNotFoundError: eval/probe_sentences.json` | dataset had `eval/` |
| `x18-close` v2 | `NameError: name 'os' is not defined` | my `os.makedirs` preceded the cell's `import os` |
| `x18-close` v3 | `AssertionError: probe_sentences.json missing` | I16's directory really was dropped by `--dir-mode skip` |
| `v020-final-eval` v1 | `JSONDecodeError` | assumed `eval_val.py` writes JSON; it writes markdown |

The pattern is uniform: **one unchecked assumption about an interface, and the
whole kernel dies.** Each is now asserted — the dataset publisher verifies by
round-trip, the generated cell's import order is checked, and the markdown parser
is pinned by tests against the exact string `eval_val.py` builds.

**The long-form probe's source was unloadable, and the mirrors were unlicensed.**
`deepmind/pg19` ships a `pg19.py` script loader and no parquet, and modern
`datasets` refuses to run dataset scripts — so the earlier "use non-streaming"
fix could never have worked. The obvious parquet mirrors
(`emozilla/pg19`, `manu/project_gutenberg`) both declare **no licence at all**,
which D44's own filter does not admit. Swapped to `sedthh/gutenberg_english`
(MIT, 37 parquet files). Its column is `TEXT`, not `text`, and getting that wrong
yields `{"n": 0}` — which reads exactly like "this source has no long documents"
and would have been taken as evidence *against* the hypothesis. A zero-row sample
is now a hard failure.

**Process note.** Four of the failures this session were invisible to every
metric we optimise, and three of them were invisible to the *tooling that
reported success*. The checks that find them are cheap and specific: verify by
round-trip, assert file formats, count parameters instead of trusting
arithmetic. All three are now in the suite.
