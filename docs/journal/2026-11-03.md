# 2026-11-03

## X40 2×2 benchmark — the failure is composition, not the test

The post-hoc clean benchmark finished. It does **not** rescue X40; it sharpens
the null.

**Design.** Seen/unseen sentence type × single/pair change, one new name pool
held constant, degenerate compositions removed. S-P is the cleanest cell: a
seen template and causal relation, with only the pair of interventions new.
The archived X40 v2 checkpoints (control/pairs/IP, both seeds) were scored on a
CPU kernel (`subhajitlucky/kalia-x40-bench`).

### What it says

- The X40 failure is real: on S-P, every arm is at chance even with a familiar
  template and causal relation.
- `number+place` is **0.0** for every model, even on the seen `put_count`
  template. The model saw the singles; it cannot combine them.
- `rename+swap` is at chance for every model.
- The above-chance pair cells are negation-marked, where the **control** is
  already at 0.32–0.33. That is a “did not”/new-name heuristic, not composition.
- The IP/pairs gains are on single operations and the easy negation pairs; they
  do not improve the hard compositions.
- Aggregate composition accuracy hides the effect. Report by operation.

### Decision

**X40 stays closed.** No 58M, no 134M, no re-score. The benchmark is the
reusable asset: it separates template novelty from composition and exposes
`rename+swap` and `number+place` as the hard cases. A future mechanism must
target those with the S-P design; beating the negation pairs or the single-op
cells is not enough. That is a new pre-registration, not a rescue.

The benchmark was scored by a CPU kernel; the first version failed only because
`enable_internet` was false and `tiktoken` could not fetch the GPT-2 BPE files.
The v2 run completed; no GPU time.

Artifacts: `docs/results/x40-bench/` (summary, 9,600 per-record rows, audit,
kernel log). Decision D69; the X40 result remains D68.
