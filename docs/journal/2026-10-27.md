# Journal — 2026-10-27 (X35: the code mixture lowers train loss, not val)

The first data-first training experiment since v0.2.0 ran overnight. It was a
registered three-arm static-mixture screen, and it returned a null: the D19
55/20/15/10 target did **nothing** on the canonical val, and a 20-point code
increase was slightly worse while cutting training loss by half a nat.

## The dessert signature, in aggregate

The 25%-code arm's training loss is **0.50 nats lower** than control at the same
step, while its held-out val is 0.0058 *worse*. The 10%-code arm is 0.10 nats
lower on train and 0.0007 better on val. More code makes the training mixture
easier to fit; it does not make the held-out distribution better. X26/X28 found
this with the adaptive policy; X35 finds the same shape in a static screen.

That is a caution for the whole data-first direction: a mixture that lowers
training loss has not shown a data win. The canonical val is the instrument.

## The instrumentation gap

S-5 asked for a per-source held-out table. The static path (`adaptive_every: 0`)
only writes `per_source_log.csv` on a reweight boundary, so the screen produced
no per-source log. The aggregate train/val divergence is reported instead, and
the archive says S-5 is unmeasured rather than implying it passed. The next
static arm needs a standalone per-source eval at the end; otherwise the gaming
check is another green check that never ran.

## Later: X36 — the memory keeps names, but is not free

The entity-memory micro finished the same evening: eight 30M arms, seeds
1338/1339, 763 steps, ~5.4 GPU-h. The memory model is a 32-slot workspace
written by a self-supervised recurrence head, read at the output, plus a copy
head. The control is a parameter-matched wider MLP.

| arm | val mean | greedy entity | half-pick | oracle |
|---|---:|---:|---:|---:|
| control | **3.8274** | 0.000 / 0.000 | 0.008 / 0.007 | 0.019 / 0.033 |
| copy | 4.0865 | 0.008 / 0.013 | 0.066 / 0.041 | 0.109 / 0.116 |
| **memory** | 3.9033 | **0.011 / 0.016** | **0.074 / 0.090** | **0.142 / 0.174** |

**M-1, M-1b, M-3 and M-4 pass. M-2 fails.** The memory keeps names better than
the control — greedy +0.0106/+0.0162, half-pick 7.4/9.0%, oracle 14.2/17.4% —
but it costs **+0.076 nats** of val against the control, far beyond the +0.010
allowance. The recurrence head learned the write signal (AUC 0.823/0.824); the
copy head alone has a signal (oracle 10.9/11.6%) but weak copy accuracy.

The pre-registered rule for "M-1 passes, M-2 fails" is explicit: report the
trade-off, **no scale**. So X36 closes as a **component result**, not a model
win. The control's extra dense capacity is a strong baseline; the memory spends
its capacity on the workspace. A val-preserving memory is a new registration,
not a tune of this one.
