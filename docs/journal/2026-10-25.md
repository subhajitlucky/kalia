## The provenance hole this run exposes

The shared X33 runner writes a manifest with the code revision, checkpoint and
stories — but at revision `7381818` it did **not** include `SEED_BASE`, the one
variable X34 moved. X34 v1 failed because the stager did not read the value back;
v2 is covered by the stager read-back, the pulled kernel source, and
`docs/results/x34/provenance.json`. But the run's own manifest still cannot name
its seed. This is the same class as the stale-bundle and notebook-gate
incidents: a record that cannot state the variable it moved is a check that did
not run. The runner now writes the field (provenance only, landed after the run).
